# AI Studio 项目文档约定 · 1.0

## 一个项目，一份入口

所有课堂任务在孩子自己的同一个本地项目目录里运行。`项目主文件.md` 是跨窗口的唯一入口；产品改名不改这个文件名，也不另建一个产品目录。每次开始先读完整主文件，再按任务读取关联材料；每次产生实际变更后更新主文件的相关章节、下一步和变更记录。不能要求孩子从头复述文件中已有的信息。

- `创业想法.md`：方向教练整理的完整愿景、选择状态、AI 作用、差异、两天主线和依据。记录的是探索方向，不是已验证的需求。
- `市场分析.md`：TAM 的范围、来源、口径、公式、低中高情景及未知。主文件保留摘要和链接。
- `One-pager.md`：从当前主文件提炼的一页讨论稿。纸上修改由孩子确认后同步回主文件，不要求重写已有的用户和地区。
- `需求文档.md`：给谁用、解决什么、功能、输入输出、界面、范围和可观察的验收标准。
- `开发计划.md`：需要哪些技术或服务、如何连接、分几步开发、每一步如何验收；不是另起一份“开发文件”。
- `开发记录.md`：实际完成、测试结果、Bug、运行入口与下一步；失败或未执行的检查不能写成通过。
- `assets/brand/`：实际生成并选定的 Logo 文件。主文件写相对路径、选定状态和版本；文字描述不能冒充图片文件。
- `founder-pitch-output/`：发布教练产物。它读取主文件和当前证据，不另设要求孩子填写的“项目发布资料.md”。旧的同名发布资料可作为历史来源读取。

文件按需创建；没有做过的环节写“未开始”，不提前虚构内容或生成一堆空白文档。只有主文件可由模板初始化。

## 主文件的固定章节

沿用 [项目主文件模板](../templates/项目主文件.md) 的章节。名称、Logo、Slogan、TAM、开发状态均在主文件有摘要或路径。阶段产物是详细证据，不取代入口。

1. 项目身份：稳定项目 ID、产品名、命名状态、Logo 路径/状态、Slogan 原文/状态/候选方向与理由、当前阶段、更新时间。
2. 用户、场景与问题：已有描述与依据，地域只在已知时填写。
3. 产品方向：愿景、特别之处、孩子的选择状态。
4. AI 核心与两天主线：真实 AI 输入→处理→结果→反馈，MVP 边界、一个差异点、后续延伸。
5. TAM 摘要：估算对象、地区、付费单位、低中高情景、单位、关键来源和假设、详细文件。
6. 文档与开发进度：文档路径、确认状态、任务完成与未完成；核心 AI 的实际接入状态。
7. 当前 Demo：如何运行、演示主路径、已测试结果、Bug 与限制。
8. 待验证与下一步：最重要的未知、下一个动作、是否等待一个具体的人类决定。
9. 变更记录：时间、环节、修改内容、证据或关联文件。

## 读写与冲突

- 先确认当前工具的工作目录就是这个项目。文件不存在时，只在当前目录查找旧的想法卡/One-pager/发布资料并复用；路径不明确时请孩子或助教选择已有项目，不搜索整台电脑、不创建另一个项目来掩盖缺文件。
- 原文件存在时先完整读取再增量更新，保留不属于本环节的段落、未知和历史。更新前把现有主文件存入 `.studio-history/`，使用含时间和随机后缀的文件名，避免同秒覆盖；写临时文件后原子替换主文件。
- 如果读取后主文件被另一个窗口修改，重新读取并合并，不能覆盖别人的更新。课堂同一时间只让一个窗口修改文档，切换前等待“已保存”。
- 当前孩子明确确认的方向优先于早期设想；当前代码、测试与运行结果决定“实际完成了什么”。代码偏离需求时分别记录计划与现实，不擅自用代码反向改变产品方向。
- 无权读取或保存时明确写“尚未读取/尚未保存”，给出需要选择的项目或可手动保存的 Markdown。不能因为聊天已输出就声称本地文件已保存。
- 未知可以存在，不用为了填满模板反复追问。事实、观察、估算、AI 建议、待验证、未完成分开；认可一个建议不等于验证它。
- 不把个人身份、账号密码或 API Key 写进主文件。模型配置只写提供方/模型名/环境变量名与接通状态。

## 环节交接

| 环节 | 先读取 | 完成后保存 |
|---|---|---|
| 创业方向 | 主文件（如有）、已有问题卡 | 创业想法.md；新建或更新项目主文件.md |
| TAM | 主文件、创业想法.md、已有市场分析 | 市场分析.md；主文件 TAM 摘要、未知与下一步 |
| 名称、Logo 与 Slogan | 主文件、已有品牌文件 | assets/brand/ 实际文件；主文件身份、路径、Slogan 候选理由及选择状态 |
| One-pager 与文档 | 主文件、纸上确认的修正 | One-pager.md；逐步生成需求文档.md、开发计划.md；主文件文档状态 |
| 开发/修复/迭代 | 主文件、需求、计划、代码与最近开发记录 | 代码与实际验证；开发记录.md；主文件当前状态/运行入口/下一步 |
| 发布 | 主文件及其证据、当前可运行项目 | founder-pitch-output/；主文件发布入口和剩余缺口 |

每次结束只报告：实际保存的文件、这次完成的内容、未完成/待验证、下一步。已有步骤未完成时接着做，不重复从头创建。

后续环节复用主文件中已确认的 Slogan 原文，不重新要求孩子写口号。仅有候选时保持待选择，不把 AI 推荐当作已确认；旧项目缺少该字段时记录未开始，不阻断无关环节。
